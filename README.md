# Gesture Lab

摄像头手势识别与三维圣诞树 Demo。使用 Vite、TypeScript、MediaPipe Gesture Recognizer 与 Three.js。

## 启动

需要 Node.js 20.19+，推荐当前 LTS。

```bash
npm install
npm run dev
```

打开终端显示的 localhost 地址，点击「开启摄像头」，允许浏览器使用摄像头。

首次安装会下载固定版本的手势模型，并把与 SDK 相同版本的 WASM 复制到 `public/mediapipe/`。识别期间从项目本地加载资源，不向服务器上传或录制摄像头画面。若首次下载中断，可以重新执行：

```bash
npm run prepare:vision
```

## 圣诞树场景（第二步）

打开页面即可看到程序生成的圣诞树：分层树冠与针叶、螺旋彩灯、立体五角星、带丝带和蝴蝶结的礼盒、飘雪及积雪底座。无需下载外部模型或图片。

拖动旋转、滚轮缩放，也可以切换彩灯、飘雪与自动旋转，点击「重播预览」重新播放树的显现。针叶与灯泡采用批量实例，雪花由 GPU 计算运动；退出页面、HMR 更新时释放渲染资源，后台暂停动画。

这一轮是普通三维场景。ASCII 字符化与麋鹿仍待后续接入。

## 连续手势互动（第三步）

开启摄像头并保持「手势联动」开启，场景从零进度等待操作：

1. **竖起食指并移动**：食指竖起作为操作开关，指尖移动距离直接推进生长。画圈、扁椭圆、画线、来回摆动都可以；六层树冠从下向上逐层显现，树顶星随顶部完成出现。
2. **拇指食指捏合一下并松开**：两指尖接触（也可比 OK），切到装饰模式。捏合只准备下一步，不直接播放装饰。
3. **再次竖起食指移动**：按移动距离从下向上增加螺旋彩灯，礼盒逐个出现。装饰不会超出已长出的树冠。
4. **双手比心放烟花**：两手拇指和食指围出心形，保持约 300ms，触发一轮烟花。保持同一姿势只放一次；松开后可再次比心（触发间隔至少 1 秒）。烟花不改变生长、装饰进度或当前模式，联动暂停时不触发。
5. **单手三指捏合落雪**：拇指、食指、中指指尖捏在一起，在画面上方左右移动；新雪花从场景顶部跟随镜像中的手部横向位置落下。松开或手离开画面后立即停止生成新雪花，已经落下的雪花自然飘落。

摄像头的大、小预览都显示当前控制位置的光点：绿色表示生长、金色表示装饰、冰蓝色表示三指落雪、灰色表示联动暂停。光点与骨架、镜像画面使用同一坐标变换。

三指落雪独立于「环境飘雪」开关，不改变树冠、装饰进度或模式。当前雪量为初始版本的 3 倍，按每秒约 108 片生成，粒子池扩大到 576 片。三指手势优先于两指捏合；结束落雪后，要先松开拇指和食指，再捏合才能切到装饰。暂停联动、关闭摄像头、页面隐藏或超过 750ms 没有新的手部结果都会停发；晚到的旧结果不能重启落雪。重新开始会清空这层雪花。

停止移动、收起食指、丢失手部追踪均停止推进；关闭摄像头或暂停联动保留两项进度，恢复后继续。进度条没有缓动延迟，也没有后台定时补进度。可点击「生长 / 装饰」切回相应模式，点击「重新开始」清空进度。

实现已移除圆弧确认、圆心拟合和角度累计。移动距离按画面比例校正，再按手掌大小归一化；累计约六个手掌尺度的有效路径可完成生长或装饰。用 0.04 个手掌尺度、且至少 4 个输入像素的空间余量过滤微小抖动，缓慢移动可逐渐越过余量，不设时间防抖；单帧超过 1.2 个手掌尺度的跳点会重新建立起点。捏合采用进入 / 退出距离阈值，保持接触只触发一次。

上指分类置信度仍为 0.30，手部检测、存在判断和追踪阈值仍为 0.35。几何判定可独立识别上指；进入后，分类不确定且食指形态仍合理时，最多维持 600ms。进入或离开这种姿态宽限时重新建立起点，避免把收指、伸指过程算成移动。明确张掌、握拳、食指收起或丢手立即结束控制；超过 750ms 未更新则首帧重新建立起点，不补算缺失动作。模式切换、暂停与恢复也会使在途的旧识别结果失效，防止旧位置被接到新动作上。

本轮没有接入光流或额外高频追踪，光点与进度仍随模型返回的关键点更新。原地扭转食指而指尖不移动不会推进。实际响应速度仍取决于设备推理耗时、光线和遮挡；放宽路径形状不等于提高模型采样率。

## 摄像头识别（第一步）

- 镜像摄像头预览及匹配的 21 点手部骨架，最多识别两只手。
- 张掌、握拳、食指向上、点赞、拇指向下、V 手势、我爱你手语及置信度。
- 在 Worker 内使用 CPU 推理，最多一帧在途，目标采样频率 20fps；界面显示实际处理频率和推理耗时。
- 已授权后可查看摄像头列表；停止后切换视频来源，再重新开启。
- 摄像头拒绝授权、未连接、被占用、断开或模型失败的错误反馈。
- 停止/退出页面释放摄像头，切换到后台暂停识别。

本轮支持食指移动、两指捏合切模式、双手比心烟花和单手三指捏合落雪。我爱你手语是模型自带的单手手势，与双手比心不同。

## 检查与构建

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

测试覆盖摄像头生命周期，以及不同形状路径、距离与速度关系、手掌尺度/画面比例、慢速移动、静止噪声、跳点、换手/丢手、姿态容错、捏合迟滞和连续进度控制。`tests/fixtures/` 的公开视频采样只用于本地模型验证，不包含在生产构建。

浏览器回放测试在开发版与生产构建中调用了真实模型，验证双手、21 个关键点、张掌、握拳、食指向上、拒绝授权提示和反复启停。记录见 [docs/verification/step1-browser.json](docs/verification/step1-browser.json)，可复用的回放函数为 [tests/browser-smoke.mjs](tests/browser-smoke.mjs)（传入 ego-browser Page、服务 URL 和 fixtureRoot）。测试以 Canvas 视频流代替实体摄像头，真实摄像头授权及不同设备识别效果需实际使用确认。

三指落雪与加量后的 39 项浏览器检查见 [hand-snow-browser.json](docs/verification/hand-snow-browser.json)：镜像发射位置、松指接触锁、分类抖动、首个过期结果/追踪中断、停发后旧雪消失、暂停/关闭摄像头，以及全部原有移动和烟花流程均通过。102 项单测、lint、typecheck 和构建通过，单测验证 108 片/秒持续发射不耗尽粒子池。浏览器使用合成关键点，不用于衡量实体摄像头识别率。

前一版移动控制与比心烟花的 26 项浏览器回放记录见 [movement-gesture-browser.json](docs/verification/movement-gesture-browser.json)：验证任意路径推进、停手、捏合、在途旧帧丢弃、烟花不改部分进度/模式、保持比心不连发，以及暂停、摄像头重开、页面恢复和资源释放。回放使用合成关键点和视频流，不代表实体摄像头识别率；截图中的手部照片仅为固定背景。76 项单测、lint、typecheck 和构建通过。移动端 390px 指南未出现横向溢出。

旧版圆弧控制的 15 项浏览器回放记录见 [continuous-gesture-browser.json](docs/verification/continuous-gesture-browser.json)，使用合成关键点验证逐层生长/装饰、转速同步、停手、捏合、丢手、暂停和摄像头恢复。噪声修正前后对比见 [rotation-noise-benchmark.json](docs/verification/rotation-noise-benchmark.json)；数值表示输入角度的累计比例，不代表实体摄像头的识别准确率。低置信度模型回放见 [lower-confidence-camera-browser.json](docs/verification/lower-confidence-camera-browser.json)。

线上部署使用 HTTPS；本地 `http://localhost` 可访问摄像头，普通 HTTP 局域网 IP 不可以。首版以桌面 Chrome/Edge 为主要验证浏览器。

部署时发布完整 `dist/`，包括 `mediapipe/` 内的模型与 WASM。模型来源、SDK 版本和模型 SHA-256 记录在自动生成的 `public/mediapipe/manifest.json` 中。
